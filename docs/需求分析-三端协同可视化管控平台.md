# 需求分析：基于数字孪生的煤矿顶板灾变智能预警与可视化决策系统（三端）

> 依据材料：
>
> - 比赛方案 PDF：CS-202612《基于数字孪生的煤矿顶板灾变智能预警与可视化决策系统比赛方案》
>
> - Web 前端参考实现：`qianduanyemian/`（index / enterprise / thinktank / supervision）
>
> - 鸿蒙端现状：`entry/src/main/ets/pages/`（HomePage / LoginPage / 三个 Dashboard / VRScene / SensorDetail）
>
> - 后端现状：`backend/`（Express + WebSocket，route：sensor / alert / analysis / supervision / auth / user / system / health）

***

## 0. 结论先行

本系统当前已具备"三端独立 + 后端接口 + WebSocket 实时 + 主题切换 + 用户/系统管理"的骨架，但对照比赛方案的核心需求与评分标准，存在**三点明显缺口**：

1. **"感知透明化"表达不足**：顶板应力场/位移场的"透明化感知"目前多为指标卡片，缺少像 Web 端那样的**三维孪生场景**入口与"场景⇄总览"联动，VRScene 处于孤立状态。
2. **"全流程数据闭环"未显式呈现**：Web 端有"采集→传输→处理→分析→预警→可视化→反馈"闭环流程表达，鸿蒙端总览没有这一可视化叙事，评审看重这个"闭环"得分点。
3. **"预警模型/多参数阈值 + 三端协同"不够实**：评分要求"可设置多个预警参数、预警准确率≥85%、误报率≤15%、三端架构清晰"，当前鸿蒙端预警管理尚无显式阈值配置页，智库端"模型指标"未用准确率/误报率量化呈现，三端之间缺少协同(联动/派单/共享)视图。

在此基础上，本分析给出：**缺口对照 → 更流畅的信息架构 → 端到端用户流程 → 可视化提升 → 可落地的优先级清单**。

## 1. 需求来源与评分约束（PDF 提炼）

| 维度       | 内容                                              |
| -------- | ----------------------------------------------- |
| **背景**   | 喀斯特煤矿深度开采，地应力增大、地质复杂，顶板事故起数与死亡人数居煤矿事故首位         |
| **根本矛盾** | 传统"单点监测、事后分析" vs 需"实时感知、智能预警、协同管控"              |
| **核心痛点** | 监测数据碎片化 / 多源信息融合困难 / 预警模型适应性差 / 可视化程度低 / 管控响应滞后 |
| **目标**   | 从"被动防治"到"主动透明防控"，响应"深地开发"战略                     |

**三大核心需求**

1. **感知透明化**——实现采掘巷道顶板**应力场、位移场**的"透明化"感知；
2. **管控协同化与可视化**——打造覆盖\*\*企业端（生产矿井）/ 智库端（高校科研）/ 监管端（集团、安监）\*\*的"三端"协同可视化管控平台；
3. **标准与集成化**——建立多源数据标准接口，解决信息孤岛，与既有安全监控/生产系统集成。

**评分标准（总分 100）**

| 大项        | 分值 | 关键点                                                                                            |
| --------- | -- | ---------------------------------------------------------------------------------------------- |
| 课题契合性     | 20 | 功能与选题及实际结合程度                                                                                   |
| 技术先进性与创新  | 25 | 技术创新 15 分（针对喀斯特优化、解决痛点）+ 预警模型算法 10 分（多源融合应力/位移、**可设置多个预警参数**、可量化指标如准确率≥85%/误报率≤15%、**三端架构清晰**） |
| 方案完整性与系统性 | 25 | 需求覆盖度 10（三大需求）+ 系统集成度与协同性 15（**采集→传输→处理→分析→预警→可视化→反馈全流程闭环**）                                   |
| 应用可行性与价值  | 30 | 技术路线可行性 / 安全与社会效益 / 经济性                                                                        |

## 4. 更流畅的信息架构与流程方案（建议）

### 4.1 三端统一信息架构（导航即角色，路径即闭环）

- 保持"三端独立 Dashboard"，但把导航统一为 **4 层：驾驶舱 → 业务 → 可视化 → 治理**，三端均以**驾驶舱/总览为首页**（KPI 摘要 + 风险指数 + 趋势 + 最近预警 + 数据闭环），与 Web 拉齐。

- 三端导航建议（比当前更贴合选题与评分）：

  - **企业端**：综合总览(驾驶舱) / 实时监测 / 预警管理 / 阈值配置 / 数据分析 / 三维孪生场景 / 三端协同 / 用户 / 系统

  - **智库端**：研究总览 / 数据集 / 分析研究 / 模型指标(准确率/误报率仪表) / 报告导出 / 用户 / 系统

  - **监管端**：监控总览(驾驶舱) / 监管预警 / 应急调度(派单) / 监管报告 / 三端态势 / 用户 / 系统

### 4.2 补全的关键页卡

1. **阈值配置页（企业端）**：对接后端阈值接口，支持"应力/位移/震动"多参数、多级别（黄/橙/红）阈值编辑 → 呼应"可设置多个预警参数"。
2. **模型指标仪表（智库端）**：把准确率/误报率/召回率做成量化卡或仪表，标注"≥85%/≤15%"目标 → 呼应预警模型先进性与量化指标。
3. **驾驶舱数据闭环（三端总览）**：复用 Web 的"采集→传输→处理→分析→预警→可视化→反馈"流程表达 → 呼应 15 分闭环。
4. **三端协同视图**：企业端可查看三端状态、向智库发起分析、向监管上报；监管端可派单至企业 → 呼应协同化。

### 4.3 端到端用户流程（更流畅，避免"验证码卡死/绕路"）

```
首页(品牌/角色选择)
   → 登录页(选三端 + 账号密码 + 图形验证码；分层校验：先账号→再密码→再验证码→再真实认证)
   → 按角色直达对应"驾驶舱/总览"（KPI 摘要，数据实时来自 DataStore + WS）
   → 从总览卡片下钻：
       企业端：总览 → 实时监测 → 预警管理(+阈值配置) → 数据分析 → 三维孪生场景(VR)
       智库端：总览 → 数据集 → 分析研究 → 模型指标(量化仪表) → 报告导出
       监管端：总览 → 监管预警 → 应急调度(派单) → 监管报告
   → 处置/反馈闭环（确认预警→更新状态→WebSocket 同步三端）
   → 用户/系统管理（昵称/改密/退出；系统信息）
```

**流畅性要点**：登录只依赖一次"三端+账号密码+验证码"，错误提示分层明确（不再一律"验证码错误"）；进入后按卡下钻，尽量减少跳转层级。

### 4.4 数据与实时同步（前后端一体）

- 以 `DataStore` 为唯一前端数据源：HTTP 拉取 + WebSocket（sensor\_update/alert\_update）主动推送，三端同源。

- 后端作为"多源数据标准接口"中枢：统一 /api/sensor、/api/alert、/api/analysis、/api/supervision 字段，承载标准与集成化需求。

### 4.5 界面与可视化提升

- 总览加**风险仪表盘 / 顶板压力趋势 / 最近预警**三个可视化组件（对齐 Web）。

- 预警用**三级颜色分级**（黄/橙/红 + 阈值条）；模型指标用**仪表/进度条**量化展示。

- 三维场景做成"总览卡片可点入"，与传感器详情/VR 联动，构成"透明感知"叙事。
