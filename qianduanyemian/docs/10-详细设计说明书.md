## 1. 引言
本文档给出模块级详细设计：数据库结构、后端各模块职责与关键算法、WebSocket 协议、前端与鸿蒙端结构、关键时序。以代码实现为准，可直接指导维护与扩展。

## 2. 总体架构（分层）
```
┌ PC 前端：index / enterprise / supervision / thinktank / bigscreen（assets/app.js、bigscreen.js、style.css）
│ 鸿蒙客户端：pages / services / components / utils
├──────────────────────── HTTP :3000 + WS :8080 ────────────────────────┐
后端：routes（9 组）→ controllers → services → config/database(pg)     │
      middleware/auth、utils/{wsHub,simulator,rate-limit,kv-store}      │
      services/{mqtt-bridge,alert,analysis,audit,session,captcha,...}   │
接入：MQTT Broker :1883 ← STM32；数据模拟器（utils/simulator）           │
存储：PostgreSQL（业务数据）+ Redis（会话/限流，可降级）                ┘
```

## 3. 数据库详细设计（PostgreSQL，库名 coal_mine_guard）
表清单：`mine`、`users`、`audit_logs`、`sensors`、`sensor_history`、`alerts`、`threshold_config`、`analysis_reports`、`dispatch_records`（完整 DDL 见 sjk/schema.sql）。

| 表 | 关键字段 | 说明 |
|---|---|---|
| mine | id, name, location, owner, status | 矿井主数据 |
| users | username(唯一), password(scrypt$salt$hash), role∈{enterprise,thinktank,supervision}, mine_id | 三端账号；种子账号 admin/mine_super/t_admin/s_admin（初始 123456） |
| sensors | id(PK,VARCHAR), type, unit, **threshold**, value, status, mine_id | 每传感器独立阈值 |
| sensor_history | sensor_id, value, created_at；索引 (sensor_id, created_at DESC) | 历史曲线 |
| alerts | id(PK), sensor_id, level∈{RED,ORANGE,YELLOW}, value, threshold, handled, handler | 预警主表，索引 created_at DESC |
| threshold_config | key_name(PK), name, value, unit | 通用阈值配置（水压/顶板下沉/震动） |
| audit_logs | action, username, role, ip, detail；索引 created_at | 操作留痕 |
| analysis_reports / dispatch_records | title, content, created_at 等 | 智库报告 / 监管派单 |

**数据一致性约定**：`sensors.threshold` 与 `threshold_config.value` 双轨并存——前者用于逐传感器判定（大屏/企业端），后者为系统级配置项；修改需保持两端同步（由业务层负责，见 4.3）。

## 4. 后端模块详细设计

### 4.1 鉴权与会话（middleware/auth.js + services/session.service.js）
- `authenticate`：取 `Authorization: Bearer <token>` → `sessionService.get(token)` 校验（Redis/内存）→ 成功挂 `req.auth = { token, role, user }` 并 `next()`；失败 401。
- `authorize(...roles)`：`req.auth.role` 不在允许列表 → 403；无 `req.auth` → 401；通过写审计。
- 登录流程：验证码（captcha.service）→ 限流（rate-limit，账号 5/分 + IP 20/分）→ authService.login 校验 → 签发 token → 重置限流。

### 4.2 阈值判定算法（services/sensor.service.js）
```
isOverThreshold(sensor):
    if sensor.threshold 为 null/undefined → false
    if sensor.type == 'ULTRASONIC_DISTANCE' → return sensor.value < sensor.threshold   # 顶板下沉：越近越险
    else → return sensor.value > sensor.threshold                                       # 其余：越高越险

alertLevelOf(sensor):                       # 仅当 isOverThreshold 时调用
    ratio = |value - threshold| / threshold
    ratio > 0.5 → RED；0.3 < ratio ≤ 0.5 → ORANGE；否则 YELLOW
```
方向说明同步在界面层展示（assets/app.js 的 `thresholdDir()`/`thresholdTxt()`）。

### 4.3 模拟器平滑游走（utils/simulator.js）
状态 `WALK[id] = { vel（漂移速度）, phase（趋势段剩余 tick）, target（阶段目标速度） }`，每 tick（约 10s）调 `nextValue(s)`：

```
nextValue(s):
    cal = MODEL_CAL[s.id]                                   # 标定参数 {normal, spread}
    若 cal 不存在（无标定）：
        phase 到期则随机新目标 target=±0.002；vel 收敛到 target（惯性系数 0.35）
        return value * (1 + vel)                            # 小扰动，无边界
    否则：
        phase 到期(4~13 tick≈40~130s)则随机 target=(rand-0.5)*0.10*spread
        vel += (target-vel)*0.35                            # 速度惯性
        vel += (anchor-value)*0.02                          # 弱均值回归锚定
        vel = clamp(vel, ±0.06*spread)
        jitter = (rand-0.5)*0.02*spread                     # 读数噪声
        nv = value + vel + jitter
        软边界：nv < anchor-3.2*spread → 反弹；nv > anchor+3.2*spread → 反弹
        return round4(max(0, nv))
```
特性：缓升缓降趋势段、无逐跳随机、边界内缓行（5000 次迭代实测零越界）。

### 4.4 MQTT 桥接（services/mqtt-bridge.js）
- 主题：上行 `sensor/<sensorId>/data`（MQTT_TOPIC 默认 `sensor/+/data`）；下行控制见 docs/05。
- `parsePayload(topic, body)` 支持三种载荷：
  1. 纯数值字符串 `"12.5"` → sensorId 取主题；
  2. `{"value":12.5}` → sensorId 取主题；
  3. `{"sensorId":"x","value":12.5}` → sensorId 覆盖主题。
  非法载荷（非数字/缺 value/JSON 损坏）→ null。
- `ingest(topic, body)`：parse → `sensorService.updateSensorData(id, value)` → 成功后 `wsHub.emit('sensor_update', ...)` + `sensor_stats`；传感器不存在返回 false 不广播。
- 异常处理：broker 不可达自动重连（start 不阻塞主服务）；解析失败仅告警不崩溃。

### 4.5 WebSocket 协议（server.js + utils/wsHub.js）
- 连接：`ws://<host>:8080?clientId=<id>`。
- 服务端消息统一 `{ type, payload }`：
  | type | payload | 触发 |
  |---|---|---|
  | connection_status | {connected, clientId, message} | 连接建立 |
  | sensor_update | 传感器数组 | 模拟器 tick / 手动干预 / MQTT 入库 |
  | sensor_stats | {total,online,warning,offline,...} | 统计变化 |
  | alert_update | 预警对象/列表 | 预警产生/处置 |
  | pong | {t} | 客户端 ping 应答 |
- 广播机制：wsHub 为发布订阅单例，`setBroadcast(fn)` 注入真实发送器（测试可替换），`emit(type,payload)` 触发。

### 4.6 限流与审计
- `utils/rate-limit.js`：基于 Redis（无 Redis 降级内存），验证码 30/分·IP、登录 5/分·账号 + 20/分·IP。
- `services/audit.service.js`：LOGIN_SUCCESS/FAIL/LOCKED、CHANGE_PASSWORD、REGISTER、THRESHOLD_UPDATE、ALERT_HANDLE/CLEAR、DISPATCH_CREATE/UPDATE 等，落 audit_logs。

## 7. 关键时序
### 7.1 登录鉴权
`前端 → GET /api/auth/captcha → POST /api/auth/login(captchaId+captchaCode) → 200 {token} → 携带 Bearer 调业务接口 / 开 WS`。

### 7.2 数据闭环（模拟器 / STM32 → 三端）
```
simulator.tick / mqtt-bridge.ingest
  → sensorService.updateSensorData（写 sensors + sensor_history）
  → alert 判定（isOverThreshold / alertLevelOf）→ alerts
  → wsHub.emit('sensor_update' | 'alert_update')
  → wss 广播 → PC 三端 / 大屏 / 鸿蒙端实时渲染
```
