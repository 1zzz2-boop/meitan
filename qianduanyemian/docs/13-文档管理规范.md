## 1. 编号规则
- 统一存放于 `qianduanyemian/docs/`，命名 `NN-标题.md`（NN 为两位序号）。
- 序号分配：01 总体方案、02 平台设计、03 模型研究、04 算法演示、05 MQTT 方案、06 SRS、07 API 文档、08 测试报告、09 运维手册、10 详细设计、11 风险登记册、12 用户手册、13 本文档。
- 新文档递增序号，不得复用；废弃文档标记 `（已废弃）` 保留不删。

## 4. 交叉引用约定
- 需求 → 设计：docs/06 追踪矩阵（FR ID → 实现文件 → 测试）。
- 设计 → 代码：docs/10 章节与 backend/routes、services、utils 一一对应。
- 测试 → 需求：docs/08 各套件覆盖的 FR 区间（见 6 需求追踪矩阵）。
- 变更任一环节时同步核对上游文档引用，避免漂移。

## 5. 变更流程（需求/代码/文档联动）
1. 提出变更（需求或缺陷）→ 登记到需求追踪矩阵（新增/修改 FR 行）；
2. 涉及行为/接口：更新 docs/06 与 docs/07；涉及模块：更新 docs/10；
3. 修改代码 → 补/改测试 → `npm test` 全绿；
4. 更新 docs/08（测试结果、遗留项）与 docs/11（风险状态）；
5. 涉及部署/操作：更新 docs/09、docs/12；
6. 修订对应文档版本号，并在本文档「修订记录汇总表」追加一行（日期+变更摘要）。

## 6. 文档质量要求
- 每个功能需求有唯一 FR ID 且可追踪；每个验收标准可验证（测试用例或手工步骤）。
- 文档不写与实现无关的虚构能力；新交付以实测为准（与 docs/08 结论一致）。
