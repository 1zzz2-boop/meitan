# 基于数字孪生的煤矿顶板灾变智能预警与可视化决策系统
## 平台系统设计方案

> 题目编号：CS-202612 · 系统名称：深地智控
> 覆盖范围："三端"协同可视化管控平台的软件架构、功能模块设计、数据库设计、接口设计、安全设计与部署设计

---

## 一、软件总体架构

平台采用**前后端分离 + 三层服务架构**，后端基于 Node.js（Express + ws），数据库使用 PostgreSQL，前端为原生 HTML/CSS/JavaScript，实现跨平台（Windows / Deepin）零构建部署。

```
┌────────────────────────────────────────────────────────────────┐
│  用户应用层                                                     │
│  企业端(enterprise.html)  智库端(thinktank.html)               │
│  监管端(supervision.html)  综合态势大屏(bigscreen.html)         │
│  统一入口(index.html 三端门户)                                  │
├────────────────────────────────────────────────────────────────┤
│  API 网关层（Express :3000，helmet + CORS + 会话鉴权）          │
│  /api/auth /api/system /api/users /api/sensor /api/alert       │
│  /api/analysis /api/supervision /api/audit /api/health         │
├────────────────────────────────────────────────────────────────┤
│  业务服务层（services/）                                        │
│  sensor · alert · analysis · supervision · auth · audit · user │
├────────────────────────────────────────────────────────────────┤
│  数据层                                                         │
│  PostgreSQL（coal_mine_guard · 8 张核心表）+ KV 缓存            │
│  WebSocket 实时通道（ws :8080）← 数据模拟器/采集端推送          │
└────────────────────────────────────────────────────────────────┘
```

**核心协作机制：**
- **实时联动**：传感器数据更新 / 预警产生 / 处置状态变化 → `wsHub` 统一广播 `sensor_update` / `alert_update` → 三端 + 大屏实时刷新；
- **全流程闭环**：采集 → 传输 → 处理 → 分析 → 预警发布 → 可视化呈现 → 管控反馈，处置结果回写数据库并广播。

### 2.3 监管端（集团 / 安监部门 · 远程管理中心）

| 预警横幅 | 未处置预警滚动发布（预警发布 → 可视化联动） |
| 全流程闭环环 | 采集→传输→处理→分析→预警→可视化→反馈 7 阶段，点击联动场景高亮 |

## 三、数据库设计

数据库：`coal_mine_guard`（PostgreSQL 12），共 8 张核心表。

### 3.1 表结构总览

| 表名 | 用途 | 关键字段 |
|---|---|---|
| `mine` | 矿井信息 | id, name, location, owner, status |
| `users` | 用户（三端角色） | id, username, password, **role(enterprise/thinktank/supervision)**, display_name, mine_id |
| `sensors` | 传感器实时状态 | id, type, name, unit, **threshold**, **value**, status, mine_id |
| `sensor_history` | 传感器历史数据 | id, sensor_id, value, created_at（按 sensor_id+时间索引） |
| `alerts` | 预警记录 | id, sensor_id, level(RED/ORANGE/YELLOW), message, value, threshold, **handled**, handler, handled_at |
| `threshold_config` | 预警阈值配置 | key_name(water_pressure/roof_sink/vibration), value, unit, description |
| `analysis_reports` | 智库分析报告 | id, title, author, content, created_at |
| `dispatch_records` | 监管应急调度 | id, title, level, content, target_mine, status, creator |

### 3.2 关键设计要点

- **传感器主键**：`id VARCHAR(64)`，与前后端点位映射一致（如 `sensor_film_pressure` / `sensor_ultrasonic` / `sensor_water_pressure` / `sensor_vibration` / `sensor_strain`），支持异构终端统一接入；
- **预警分级**：`level` 限定 RED / ORANGE / YELLOW，由"阈值偏离比"算法自动判定；
- **阈值联动**：`threshold_config` 与 `sensors.threshold` 同步更新（水压/顶板下沉/震动映射），实现多参数动态配置；
- **历史归档**：`sensor_history` 按 (sensor_id, created_at DESC) 建索引，支撑 24h 趋势与模型训练数据回流；
- **三端权限**：`users.role` 控制各端访问与写操作权限（如预警处置限 enterprise/supervision、报告生成限 thinktank）。

## 四、数据接口设计

### 4.1 REST API（HTTP :3000）

| 模块 | 接口 | 说明 |
|---|---|---|
| 认证 | `POST /api/auth/login` | 登录（三端角色），返回会话令牌 |
| 系统 | `GET /api/health`、`GET /api/system/*` | 健康检查与系统公开信息 |
| 传感器 | `GET /api/sensor/all` · `GET /api/sensor/:id` · `GET /api/sensor/type/:type` | 实时数据查询 |
| 传感器 | `POST /api/sensor/update` | 数据写入（采集端/模拟器），写入后立即 WebSocket 广播 |
| 阈值 | `GET /api/sensor/thresholds` · `POST /api/sensor/thresholds` | 阈值查询 / 动态配置（限 enterprise/supervision） |
| 预警 | `GET /api/alert/all` · `GET /api/alert/unhandled` | 预警查询 |
| 预警 | `POST /api/alert/handle` · `POST /api/alert/clear` | 处置 / 清空（限 enterprise/supervision） |
| 分析 | `GET /api/analysis/trend` · `/threat` · `/stats` · `/model-metrics` | 趋势 / 威胁度 / KPI / 模型指标 |
| 分析 | `GET /api/analysis/reports` · `POST /api/analysis/reports` | 报告查询 / 生成（限 thinktank） |
| 监管 | `/api/supervision/*` | 监控总览 / 调度 / 报告 |
| 审计 | `/api/audit/*` | 操作审计留痕 |

### 4.2 WebSocket 事件（ws :8080）

| 事件 | 方向 | 说明 |
|---|---|---|
| `connection_status` | 服务端 → 客户端 | 连接确认 / 断开通知 |
| `sensor_update` | 服务端 → 客户端 | 传感器数据全量广播（含大屏按住爬升演示写入） |
| `alert_update` | 服务端 → 客户端 | 新预警实时推送（各端响铃/高亮/横幅） |

### 4.3 数据格式标准

统一 JSON：`{ id, type, name, unit, threshold, value, status, isWarning }`；预警：`{ id, sensor_id, level, message, value, threshold, handled, created_at }`，天然支持与既有安全监控系统、生产系统集成共享，解决"信息孤岛"。

## 五、安全设计

| 维度 | 措施 |
|---|---|
| 传输安全 | helmet 安全头、CORS 策略、可选 HTTPS 部署（自签证书支持） |
| 鉴权 | 登录颁发服务端会话令牌，`authenticate` 中间件统一校验 |
| 授权 | `authorize('enterprise','supervision')` 等角色级写操作控制 |
| 数据安全 | 密码不可逆存储（password 工具）、敏感操作审计留痕 |
| 容错 | 数据库连接失败即停、WebSocket 断线自动重连（前端 `wsClient`） |

## 七、综合态势大屏与建模场景联动设计（重点）

大屏以 SVG 数字孪生场景为核心，实现**数据驱动 + 交互驱动**的双向联动：

1. **数据 → 场景**：传感器实时值驱动测点颜色（正常/黄/橙/红）、预警光晕脉冲、KPI 带数值、风险指数环；
2. **交互 → 场景 → 数据**：
   - 单击测点 → 多源融合卡（实时值/阈值/威胁度/历史走势/力学机理/布设策略）；
   - **按住测点 → 数值爬升 + 关联应力/位移/溶洞云图按物理机理扩张（多场耦合），松开 → 逐步回落**；
   - 点击 F₁ 断层/溶洞/含水层 → 地质素描信息卡（构造性质/导水危险性/灾变关联）；
   - 点击 LoRa 网关 → 监测网络拓扑卡（分组链路/速率/在线状态/集成说明）；
   - 阈值滑杆 → 实时更新预警状态并同步数据库；
   - 预警列表点击 → 场景定位 + 预警依据弹窗 + 确认处置；
3. **联动闭环**：大屏按住爬升写入 → 后端 WebSocket 广播 → 三端同步可见，体现"采集→传输→分析→预警→可视化→反馈"全链路。
